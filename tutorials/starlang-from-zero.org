* What StarLang is

StarLang is a contract language, compiler, and actor runtime implemented in Common Lisp.

This tutorial only covers behavior that exists on =main=.

A =.star= file is Lisp-shaped, but it is not Common Lisp source. StarLang parses it with its own parser:

#+begin_example
.star source
    |
    v
read-star-syntax
    |
    v
expand-star-syntax
    |
    v
validate-star-core
    |
    v
compile-star-core
    |
    v
normalized IR
#+end_example

* Run it

#+begin_src sh
git clone https://github.com/lost-rob0t/star-lang
cd star-lang
nix develop
nix run .#tests
nix flake check -L
#+end_src

Or load it in SBCL:

#+begin_src lisp
(require :asdf)
(asdf:load-system :starlang-prototype)
#+end_src

* Your first library

Create =hello.star=:

#+begin_src lisp
(spec-library "org.example/hello@1"
  (:version "1.0.0")

  (document greeting
    (:persistence persistent)
    (text string :required)))
#+end_src

Load it:

#+begin_src lisp
(defparameter *hello*
  (star-lang.api:load-star-file #P"hello.star"))
#+end_src

The public API also exposes the compiler phases directly:

#+begin_src lisp
(defparameter *syntax*
  (star-lang.api:read-star-syntax source))

(defparameter *expanded*
  (star-lang.api:expand-star-syntax *syntax*))

(star-lang.api:validate-star-core *expanded*)

(defparameter *ir*
  (star-lang.api:compile-star-core *expanded*))
#+end_src

Use those phases when debugging instead of treating every failure as a loader problem.

* Types

StarLang implements constrained scalar types:

#+begin_src lisp
(scalar task-id
  (:base string
   :pattern "^[a-z0-9-]{3,64}$"))
#+end_src

Enums:

#+begin_src lisp
(enum task-status
  (queued running completed failed))
#+end_src

Current contracts also use types such as:

#+begin_example
string
integer
decimal
boolean
symbol
map
reference
iso-date
iso-datetime
(list string)
#+end_example

* Documents and messages

A document describes typed data:

#+begin_src lisp
(document task
  (:persistence persistent)
  (taskId task-id :required)
  (description string :required)
  (status task-status :required))
#+end_src

A message describes actor/runtime communication:

#+begin_src lisp
(message run-task
  (:fields
   ((taskId task-id :required))))
#+end_src

They are separate contracts. A command message is not automatically the document produced by handling it.

* A small library

#+begin_src lisp
(spec-library "org.example/tasks@1"
  (:version "1.0.0")

  (scalar task-id
    (:base string
     :pattern "^[a-z0-9-]{3,64}$"))

  (enum task-status
    (queued running completed failed))

  (document task
    (:persistence persistent)
    (taskId task-id :required)
    (description string :required)
    (status task-status :required))

  (message run-task
    (:fields
     ((taskId task-id :required))))

  (message task-completed
    (:fields
     ((taskId task-id :required)
      (summary string :required)))))
#+end_src

Load it:

#+begin_src lisp
(defparameter *tasks*
  (star-lang.api:load-star-file #P"tasks.star"))
#+end_src

* Creating documents

#+begin_src lisp
(defparameter *task*
  (star-lang.api:create-document
   *tasks*
   "task"
   '(("taskId" . "task-001")
     ("description" . "Learn StarLang")
     ("status" . queued))
   :dataset "tutorial"))
#+end_src

Encode it:

#+begin_src lisp
(defparameter *encoded*
  (star-lang.api:encode-document
   *task*
   :key-style :camel
   :couchdb t))
#+end_src

Decode it:

#+begin_src lisp
(defparameter *decoded*
  (star-lang.api:decode-document
   *tasks*
   "task"
   *encoded*))
#+end_src

Field spelling such as =taskId= is preserved in the contract and wire representation.

* IDs and relations

The document runtime implements:

- ULID IDs;
- UUIDv4 IDs;
- deterministic digest IDs.

The public helpers include:

#+begin_src lisp
star-lang.api:generate-id
star-lang.api:make-ulid
star-lang.api:make-uuidv4
star-lang.api:make-digest-id
#+end_src

Relations can be constructed with:

#+begin_src lisp
(star-lang.api:relate-documents
 graph
 source-document
 destination-document
 :predicate "member-of")
#+end_src

* Imports

StarLang implements versioned, digest-checked library imports:

#+begin_src lisp
(import "org.starintel/core@1"
  :version "1.0.0"
  :digest "sha256:...")
#+end_src

See the real fixtures for working import examples.

* Actors

The runtime implements native and external actor definitions, actor registration, spawning, tell/ask delivery, mailbox limits, actor references, and deterministic dispatch.

The main runtime package is =STARLANGRUNTIME=, also nicknamed =STARLANG-RUNTIME=.

Useful exported operations include:

#+begin_src lisp
starlang-runtime:make-runtime
starlang-runtime:create-native-actor
starlang-runtime:create-external-actor
starlang-runtime:register-actor
starlang-runtime:spawn
starlang-runtime:tell
starlang-runtime:ask
starlang-runtime:dispatch-next
starlang-runtime:run-until-idle
#+end_src

The deterministic wire dispatcher is also implemented in the runtime package, including command idempotency, deferred completion, retry, failure, and redelivery support.

* =star://= service URIs

Yes, =star://= is implemented.

The exact format is:

#+begin_example
star://domain:address:actor-name
#+end_example

Example:

#+begin_example
star://bbp:localhost:nmap
#+end_example

The canonical implementation lives in =STAR-ACTOR-PROTOCOL=.

#+begin_src lisp
(defparameter *uri*
  (star-actor-protocol:parse-star-service-uri
   "star://bbp:localhost:nmap"))

(star-actor-protocol:star-service-uri-domain *uri*)
(star-actor-protocol:star-service-uri-address *uri*)
(star-actor-protocol:star-service-uri-actor-name *uri*)
(star-actor-protocol:star-service-uri-string *uri*)
#+end_src

Tokens must be non-empty lowercase ASCII using letters, digits, =.=, =_=, or =-=.

The actor name in the URI can also be checked against an actor contract with:

#+begin_src lisp
(star-actor-protocol:canonical-star-service-uri-for-actor
 "nmap"
 "star://bbp:localhost:nmap")
#+end_src

* Runtime directory resolution

The runtime implements service lookup by =star://= URI.

The exported API includes:

#+begin_src lisp
starlang-runtime:make-runtime-directory-port
starlang-runtime:runtime-directory-snapshot
starlang-runtime:resolve-star-service-uri
#+end_src

It has explicit service-not-found and service-unavailable errors rather than collapsing every failure into =NIL=.

=STAR-ACTOR-PROTOCOL= also implements portable wire envelopes and lifecycle envelopes.

Exported constructors and validators include:

star-actor-protocol:validate-lifecycle-envelope
star-actor-protocol:make-wire-envelope

#+end_src

* Runtime pieces that exist

The repository currently contains implementations for:

- actor protocol and actor references;
- =star://= service URIs;
- actor runtime and runtime directory;
- deterministic dispatcher and idempotency;
- mailboxes;
- journals;
- leases;
- supervision;
- capability handling;
- RabbitMQ transport binding;
- HTTP port;
- process port;
- Sento / CL-GServer compatibility;
- canonical JSON;
- document construction and relation compatibility.

That is the runtime surface this tutorial refers to. It does not assume unimplemented backends or proposed language forms.

* Debugging map

| Symptom | Start here |
|-
| Source will not parse | =read-star-syntax= |
| Macro expansion is wrong | =expand-star-syntax= |
| Contract validation is wrong | =validate-star-core= |
| IR is wrong | =compile-star-core= |
| Import fails | loader/import code |
| Document IDs/fields are wrong | document runtime |
| =star://= is rejected | =STAR-ACTOR-PROTOCOL= service URI parser |
| Service cannot resolve | runtime directory |
| Actor delivery is wrong | actor runtime + dispatcher |
| Duplicate command executes twice | dispatcher idempotency + journal |
