* Goal

This tutorial is for learning =prolog-rlm= well enough to run it, debug it, extend it, and build bounded agentic RLM systems on top of it.

It is based on the implementation, tests, and current documentation in the repository rather than on a generic description of Recursive Language Models.

By the end you should be able to:

- explain what =prolog-rlm= means by an RLM;
- explain why Prolog owns execution semantics while the model chooses semantic strategy;
- run the repository's deterministic test and conformance suites;
- register and inspect opaque external contexts;
- use bounded =peek=, =slice=, =search=, =partition=, =map=, and =reduce= operations;
- configure OpenRouter or another OpenAI-compatible provider;
- understand and execute the closed typed-plan AST;
- define capability-gated tools without exposing arbitrary =call/1= to model output;
- distinguish =llm_query/3=, =rlm_query/4=, and =rlm_completion/4=;
- understand recursive depth, capability narrowing, cost, token, tool, context, time, and output budgets;
- use structured outcomes, inspection, and bounded plan repair;
- create supervised logical agents with bounded mailboxes and worker pools;
- compile and run durable state graphs with checkpoints, interrupts, and resume;
- publish durable artifacts and rebuild bounded fresh-root context from them;
- understand adaptive recursion routing instead of treating recursion as the default;
- understand the version-neutral MCP boundary;
- run deterministic and live benchmark modes;
- complete a practical repository-analysis RLM project.

* 1. What prolog-rlm actually is

The short version is:

#+begin_quote
=prolog-rlm= is a SWI-Prolog-native language-model harness and agent runtime where the model may choose strategy, but Prolog validates and owns execution.
#+end_quote

That distinction is the project.

An ordinary LLM application often looks roughly like this:

#+begin_example
huge prompt
  -> model
  -> text answer
#+end_example

An RLM-style application treats the external context as something the model can *operate on* without stuffing all of it into a single prompt:

#+begin_example
query + external context
        |
        v
opaque context handle
        |
        v
model selects bounded strategy
        |
        v
typed symbolic plan
        |
        v
Prolog validates capabilities + budgets
        |
        v
context / model / tool / recursive / agent operations
        |
        v
structured trajectory + result
#+end_example

The model is not handed unrestricted Prolog execution. It does not get arbitrary =call/1=, =shell/1=, =consult/1=, filesystem access, or network access just because it emitted text that looks executable.

The central design rule is:

#+begin_quote
The language model chooses semantic strategy; Prolog owns execution semantics.
#+end_quote

* 5. Opaque contexts are the first RLM primitive

Import the context runtime directly:

#+begin_src prolog
:- use_module('prolog/rlm_context').
#+end_src

The memory backend accepts only explicit text or term sources:

#+begin_src prolog
context_register(text(Text), Options, Outcome).
context_register(terms(Terms), Options, Outcome).
#+end_src

Try it:

#+begin_src prolog
?- context_register(
       text("alpha\nbeta needle\ngamma\nneedle delta\n"),
       [],
       ok(Ref)),
   get_dict(handle, Ref, Handle).
#+end_src

The result contains a versioned opaque handle and metadata. It does *not* hand the external payload to every later model call.

The initial memory backend advertises no implicit filesystem or network authority. A value such as =file('/etc/passwd')= is not silently dereferenced as context.

Default projection bounds are roughly:

#+begin_src prolog
[max_results(32), max_bytes(16384), time_limit(0.25)]
#+end_src

These are part of the execution model, not decoration.

* 6. Context operations

Given =Handle= from the previous section:

**Peek**

#+begin_src prolog
?- context_peek(Handle, head(12), [], Outcome).
#+end_src

**Slice**

#+begin_src prolog
?- context_slice(Handle, 6, 20, [], Outcome).
#+end_src

Text indexes are character based. Term-context slices are item based.

**Search**

#+begin_src prolog
?- context_search(Handle, "needle", [], Outcome).
#+end_src

Text search is line based. Term search uses a stable textual representation.

**Partition**

#+begin_src prolog
?- context_partition(Handle, lines(2), [], Outcome).
#+end_src

**Allow-listed map**

#+begin_src prolog
?- context_map(Handle, lowercase, [], Outcome).
#+end_src

The current transform vocabulary includes =identity=, =lowercase=, =uppercase=, and =length=.

**Allow-listed reduce**

#+begin_src prolog
?- context_reduce(Handle, count, [], Outcome).
#+end_src

Reducers include =count= and =byte_count=.

**Trace**

#+begin_src prolog
?- context_trace(Handle, 20, Outcome).
#+end_src

The important security property is that =map= and =reduce= do not accept arbitrary caller/model predicates. They select from a closed vocabulary.

**Exercise:** register a =terms([...])= context containing small Prolog facts as data. Compare =peek(item(N))=, =slice=, =search=, =map(length)=, and =reduce(count)=.

* 7. Typed plans: model strategy becomes closed data

Import the plan layer directly when working below =rlm_completion/4=:

#+begin_src prolog
:- use_module('prolog/rlm_plan').
#+end_src

The main flow is:

#+begin_src prolog
plan_parse(+ModelOutput, -Outcome).
plan_normalize(+PlanLike, -Outcome).
plan_validate(+Plan, +Capabilities, +Budget, -Outcome).
plan_execute(+ValidatedPlan, +RuntimeOptions, +Inputs, -Outcome).
plan_run(+PlanLike, +Capabilities, +RuntimeOptions, +Inputs, -Outcome).
#+end_src

The closed AST currently contains:

#+begin_src prolog
context(HandleExpr, Action, Bind).
model(ProviderName, PromptExpr, RequestOptions, Bind).
rlm(SubPlan, Bind).
tool(ToolName, ArgsExpr, Bind).
parallel(SubPlans, Bind).
retry(Attempts, SubPlan, Bind).
checkpoint(Label).
final(ValueExpr).
#+end_src

Expressions are also closed:

#+begin_src prolog
literal(Value).
input(Name).
var(Name).
field(BaseExpr, Key).
list(Exprs).
object(KeyExprPairs).
#+end_src

That means a model can say “call tool =project_read=” or “search this context,” but it cannot supply a new Prolog closure to execute.

* 8. Execute a model-free context plan first

Before involving an LLM, prove that you understand the plan runtime itself.

Assume =Handle= is an existing context handle:

#+begin_src prolog
Plan = plan([
    context(input(context), search("needle"), hits),
    final(var(hits))
]),
Capabilities = [context(search)],
Inputs = _{context:Handle},
plan_run(Plan, Capabilities, [], Inputs, Outcome).
#+end_src

Why this matters: if this fails, you have a plan/context problem, not an LLM problem.

Whole-plan validation occurs before execution. The runtime checks at least:

- operation vocabulary;
- exactly one final step, at the end;
- use-before-bind;
- duplicate bindings;
- allow-listed context actions;
- capabilities;
- nested recursion/retry/parallel structure;
- worst-case budget estimates;
- provider/tool preflight.

A validation failure should produce no earlier partial tool/model/context side effects.

* 9. Capabilities are explicit authority

Capabilities look like ordinary Prolog terms:

#+begin_src prolog
context(search).
context(slice).
model(openrouter).
tool(project_read).
rlm.
parallel.
retry.
checkpoint.
filesystem(read).
network(http).
process(exec).
mcp(tools).
#+end_src

The existence of a capability term does not grant it. It must appear in the active capability set.

Children narrow authority:

#+begin_src prolog
?- capabilities_narrow(
       [rlm, model(openrouter), tool(project_read)],
       [model(openrouter)],
       Outcome).
#+end_src

This is valid.

Trying to give the child something the parent lacks fails closed:

#+begin_src prolog
?- capabilities_narrow(
       [model(openrouter)],
       [model(openrouter), tool(project_read)],
       Outcome).
#+end_src

The second request is capability widening and is rejected.

* 10. Trusted tools

Import the registry:

#+begin_src prolog
:- use_module('prolog/rlm_tool').
#+end_src

The lifecycle is:

#+begin_src prolog
tool_registry_create(Registry).
tool_register(Registry, Schema, TrustedHandler, Outcome).
tool_discover(Registry, Schemas).
tool_lookup(Registry, Name, Outcome).
tool_invoke(Registry, Capabilities, Name, Args, Options, Outcome, Trace).
tool_registry_destroy(Registry).
#+end_src

A minimal custom tool can look like:

#+begin_src prolog
count_text(Args, Count) :-
    get_dict(text, Args, Text),
    string_length(Text, Count).

count_text_schema(
    tool_schema{
        name:count_text,
        description:"Count characters in a string",
        capability:tool(count_text),
        arguments:_{
            type:object,
            required:[text],
            additional_properties:false,
            properties:_{text:_{type:string}}
        },
        result:_{type:integer},
        limits:tool_limits{
            time_limit:1.0,
            max_output_bytes:1024
        }
    }).
#+end_src

Register and call it:

#+begin_src prolog
tool_registry_create(Registry),
count_text_schema(Schema),
tool_register(Registry, Schema, user:count_text, ok(_)),
tool_invoke(
    Registry,
    [tool(count_text)],
    count_text,
    _{text:"prolog"},
    [],
    Outcome,
    Trace).
#+end_src

The handler is trusted host configuration. The model may select =count_text= by name, but never receives the closure =user:count_text=.

* 11. The built-in project_read tool

The first real local tool is deliberately narrow:

#+begin_src prolog
register_project_read_tool(
    Registry,
    '/srv/project',
    [max_file_bytes(8192), time_limit(1.0)],
    Outcome).
#+end_src

It requires:

#+begin_src prolog
tool(project_read)
#+end_src

It reads one regular UTF-8 file under an explicitly configured root.

It rejects absolute paths, =.= / =..= traversal, backslash paths, NUL-containing paths, and symlink components. Registering it does not magically grant general filesystem, process, shell, or network access.

To expose registry tools to a typed plan:

#+begin_src prolog
Caps = [tool(project_read)],
tool_registry_runtime_tools(Registry, Caps, RuntimeTools),
plan_run(
    Plan,
    Caps,
    [tools(RuntimeTools)],
    Inputs,
    Outcome).
#+end_src

Notice the double check:

1. the plan must validate against =tool(project_read)=;
2. registry invocation independently authorizes the same capability.

* 12. Model providers

The chain layer is provider neutral:

#+begin_src prolog
:- use_module('prolog/rlm_chain').
#+end_src

OpenRouter configuration:

#+begin_src prolog
?- openrouter_provider('openrouter/free', Provider).
#+end_src

The provider term stores =credential(env('OPENROUTER_API_KEY'))= rather than the resolved secret.

Set the credential in the environment before running a live call:

#+begin_src sh
export OPENROUTER_API_KEY='...'
#+end_src

A direct model request:

#+begin_src prolog
openrouter_provider('openrouter/free', Provider),
Request = model_request{
    messages:[message{role:user, content:"Reply with OK."}],
    options:_{max_tokens:32}
},
model_complete(Provider, Request, Outcome).
#+end_src

For another compatible endpoint:

#+begin_src prolog
openai_compatible_provider(
    'https://example.invalid/v1/chat/completions',
    env('EXAMPLE_API_KEY'),
    'example/model',
    Provider).
#+end_src

For a local endpoint requiring no credential, use =none= instead of a raw secret.

* 13. llm_query/3 vs rlm_query/4 vs rlm_completion/4

These are different levels of abstraction.

**=llm_query/3=**

One bounded model call:

#+begin_src prolog
?- use_module('prolog/rlm').
?- llm_query(
       "Reply with the atom ok.",
       [budget(_{max_total_tokens:256, max_cost_usd:0.05})],
       Outcome).
#+end_src

Unless a provider is supplied explicitly, completion code builds the default OpenRouter provider.

**=rlm_query/4=**

A bounded recursive child model query over a supplied sub-context:

#+begin_src prolog
?- rlm_query(
       "Summarize the child context.",
       text("small child context"),
       [depth(1), budget(_{max_recursion_depth:1})],
       Outcome).
#+end_src

**=rlm_completion/4=**

The full root supervisor:

#+begin_example
root query
  -> context registration/handle
  -> root planner model
  -> JSON typed plan
  -> parse + validate
  -> execute context/model/tool/rlm operations
  -> enforce total budgets
  -> structured result + trajectory
#+end_example

Do not use =rlm_completion/4= when you only need a direct provider call. Do not use =llm_query/3= when the task specifically needs model-selected context decomposition.

* 15. A real agentic RLM shape

The repository's live completion test proves the important production path:

1. a real OpenRouter root planner is called;
2. it emits JSON for a typed plan;
3. the plan slices an opaque context;
4. it calls the registered =project_read= tool;
5. it performs exactly one depth-1 recursive child model call;
6. the runtime verifies tool authorization, recursion depth, HTTP success, model-call count, and ordered plan transitions.

A tutorial-scale setup begins like this:

#+begin_src prolog
:- use_module('prolog/rlm').
:- use_module('prolog/rlm_tool').

run_demo(Outcome) :-
    tool_registry_create(Registry),
    setup_call_cleanup(
        register_project_read_tool(
            Registry,
            '.',
            [max_file_bytes(16384), time_limit(1.0)],
            ok(_)),
        run_demo_with_registry(Registry, Outcome),
        tool_registry_destroy(Registry)).

run_demo_with_registry(Registry, Outcome) :-
    Context = text(
        "You are a recursive child. Read only the selected context and answer briefly."),
    Options = [
        capabilities([
            rlm,
            context(slice),
            tool(project_read),
            model(openrouter)
        ]),
        child_capabilities([model(openrouter)]),
        tool_registry(Registry),
        planner_attempts(2),
        planner_max_tokens(1400),
        context_options([
            max_bytes(4096),
            time_limit(1.0)
        ]),
        budget(_{
            max_recursion_depth:1,
            max_model_calls:4,
            max_tool_calls:1,
            max_context_ops:1,
            max_total_tokens:12000,
            max_cost_usd:0.25,
            time_limit:150.0
        })
    ],
    rlm_completion(
        "Inspect a bounded context slice and README, then use one child model call.",
        Context,
        Options,
        Outcome).
#+end_src

For reproducible acceptance behavior, add a =planner_instruction(...)= that constrains the planner to an exact plan shape, like =test/live_completion_openrouter_test.pl= does.

* 16. Cancellation is a control signal

Create a token:

#+begin_src prolog
rlm_cancellation_token(Token).
#+end_src

Pass it to a completion:

#+begin_src prolog
[cancel_token(Token)]
#+end_src

Cancel from another control path:

#+begin_src prolog
rlm_cancel(Token).
#+end_src

The implementation actively signals the thread running the completion. Cancellation and time-limit signals are intentionally preserved as control signals instead of being swallowed and misclassified as ordinary tool/model errors.

The deterministic suite includes both pre-planner cancellation and cancellation of a pending model call.

* 17. Structured outcomes: Prolog failure is not one generic error

The outcome layer uses canonical statuses including:

- =success=;
- =logical_failure=;
- =timeout=;
- =depth_exhausted=;
- =resource_exhausted=;
- =capability_denied=;
- =validation_failure=;
- =exception=.

This is extremely Prolog-ish in the good way: logical failure should not be flattened into an exception.

Inspect a plan without executing it:

#+begin_src prolog
plan_inspect(Plan, Capabilities, Budget, Inspection).
#+end_src

Inspect a trusted predicate's metadata:

#+begin_src prolog
predicate_inspect(my_module:worker(_), Inspection).
#+end_src

Wrap trusted goals:

#+begin_src prolog
goal_outcome(member(X, [a,b]), [], Outcome).
#+end_src

The goal outcome preserves residual constraints from =copy_term/3= instead of silently discarding attributed-variable state.

* 18. Bounded plan repair

Repair is explicit and budget preserving:

#+begin_src prolog
plan_repair(
    Plan,
    Capabilities,
    RuntimeOptions,
    Inputs,
    TrustedRepairHandler,
    Outcome).
#+end_src

The repair handler receives structured observations, not scraped stderr:

#+begin_src prolog
repair_observation{
    attempt:Attempt,
    status:Status,
    phase:Phase,
    error:StructuredError,
    trace:BoundedTrace,
    budget_remaining:Remaining
}.
#+end_src

The crucial invariant:

#+begin_quote
Repair does not reset the execution budget.
#+end_quote

If the first attempt consumed tool calls, steps, output bytes, or wall time, the repaired attempt receives what remains.

**Exercise:** write a deterministic repair handler that replaces an invalid unknown tool with a known safe tool. Verify that a validation failure can be repaired without consuming execution counters, then compare that with an execution-time failure.

* 19. Supervised logical agents

The agent runtime uses SWI engines/state machines, finite message queues, and a shared bounded worker pool.

It deliberately does not allocate one permanent OS thread per logical agent.

Public lifecycle:

#+begin_src prolog
agent_runtime_create(+Options, -Runtime).
agent_runtime_destroy(+Runtime).
agent_runtime_status(+Runtime, -Status).
agent_spawn(+Runtime, +Parent, +Spec, +Capabilities, -Outcome).
agent_send(+Runtime, +Agent, +Message, +Options, -Outcome).
agent_pump(+Runtime, +Agent, +Options, -Outcome).
agent_status(+Runtime, +Agent, -Outcome).
agent_children(+Runtime, +Agent, -Children).
agent_cancel(+Runtime, +Agent, +Reason, -Outcome).
agent_trace(+Runtime, -Events).
#+end_src

A minimal supervision tree:

#+begin_src prolog
run_agents :-
    setup_call_cleanup(
        agent_runtime_create(
            [root_capabilities([
                 tool(spawn_agent),
                 tool(read)
             ])],
            Runtime),
        (
            agent_spawn(
                Runtime,
                none,
                agent_spec(root),
                [tool(spawn_agent), tool(read)],
                ok(Root)),
            agent_spawn(
                Runtime,
                Root,
                agent_spec(child),
                [tool(read)],
                ok(Child)),
            agent_children(Runtime, Root, Children),
            format('root=~q child=~q children=~q~n',
                   [Root, Child, Children])
        ),
        agent_runtime_destroy(Runtime)).
#+end_src

The child cannot add authority the root does not possess.

* 20. Mailboxes and backpressure

The message vocabulary is closed around terms such as:

#+begin_src prolog
request(RunId, CallId, Work).
result(CallId, Result).
spawn(Parent, Child, Spec, Capabilities).
cancel(RunId, Reason).
checkpoint(RunId, Label).
budget_exhausted(RunId, Kind).
#+end_src

Mailboxes are finite.

That means saturation becomes a visible =mailbox_full= outcome instead of uncontrolled heap growth.

Blocking trusted work is moved through a bounded thread pool configured with options such as:

#+begin_src prolog
worker_count(2).
worker_backlog(8).
worker_handler(my_module:worker_handler).
#+end_src

This gives you many logical agents with a hard ceiling on simultaneous blocking host operations.

* 21. spawn_agent inside a typed plan

The plan form:

#+begin_src prolog
plan([
    spawn_agent(agent_spec(child), [tool(read)], child),
    final(var(child))
]).
#+end_src

is syntax sugar. It normalizes to the existing trusted tool boundary:

#+begin_src prolog
tool(
    spawn_agent,
    literal(agent_spawn_request{
        spec:Spec,
        capabilities:Capabilities
    }),
    Bind).
#+end_src

The host registers the trusted adapter:

#+begin_src prolog
[tools([
    tool(spawn_agent,
         rlm:agent_tool_handler(Runtime, Parent))
])]
#+end_src

There is no second unsafe “agent evaluator.” Agent creation still consumes normal plan/tool budgets and still requires =tool(spawn_agent)=.

* 22. Durable state graphs

The graph runtime separates declarative graph data from trusted executable closures.

A tiny graph:

#+begin_src prolog
graph(
    counter,
    [field(count, integer, 0, sum)],
    [node(increment, increment_handler)],
    [edge(start, increment),
     edge(increment, end)]
).
#+end_src

Trusted host registry:

#+begin_src prolog
Registry = [
    handler(increment_handler, my_graph:increment)
].
#+end_src

Handler shape:

#+begin_src prolog
increment(_State, _Context, update(_{count:1})).
#+end_src

Compile before running:

#+begin_src prolog
graph_compile(Spec, Registry, [], ok(Compiled)),
graph_run(Compiled, _{}, [], Outcome).
#+end_src

Compilation checks graph structure before side effects: unique state fields/nodes, start/end invariants, registered handler/router references, reachability, and a structural path to =end=.

Loops are allowed structurally, but runtime budgets cap total steps and visits per node.

* 23. Graph interrupts, checkpoints, and resume

Open an in-memory checkpoint backend:

#+begin_src prolog
graph_backend_open(memory, Backend).
#+end_src

A node may return:

#+begin_src prolog
interrupt(needs_approval, _{status:waiting}).
#+end_src

Run with a stable ID:

#+begin_src prolog
graph_run(
    Compiled,
    _{},
    [backend(Backend), run_id(review_42)],
    ok(Paused)).
#+end_src

Resume:

#+begin_src prolog
graph_resume(
    Compiled,
    Backend,
    review_42,
    approved,
    [],
    Outcome).
#+end_src

Resume can atomically include a state patch:

#+begin_src prolog
resume(approved, _{approved:true})
#+end_src

The persistent backend is:

#+begin_src prolog
graph_backend_open(
    persist('/var/lib/my-app/graph.db'),
    Backend).
#+end_src

The repository tests restart a graph across two separate =swipl= processes, which is the right kind of durability test: it proves the resumed process reconstructs executable closures from code while loading only persisted ground graph state/events.

* 24. Durable artifacts are not transcripts

Artifacts solve a different problem from graph checkpoints.

#+begin_example
conversation transcript
    = model-local history

graph checkpoint
    = execution state for resuming a run

artifact store
    = selected durable summaries/findings/blackboards shared across runs
#+end_example

Open a store:

#+begin_src prolog
artifact_store_open(memory, ok(Store)).
#+end_src

Publish:

#+begin_src prolog
artifact_put(
    Store,
    [project, demo],
    working_summary,
    summary,
    _{text:"bounded durable state"},
    _{producer:manual_tutorial},
    Outcome).
#+end_src

The store allocates immutable monotonically increasing versions per namespace/key.

Build a bounded fresh-root pack:

#+begin_src prolog
artifact_context_pack(
    Store,
    [project, demo],
    [max_items(8), max_chars(4000), consumer(next_root)],
    Outcome).
#+end_src

A later root gets selected compact state, not an implicit replay of every earlier model message.

* 25. Stale artifact references are explicit

Artifacts are immutable by version.

Writing a newer version supersedes the old one without deleting it.

Use:

#+begin_src prolog
artifact_ref_status(Store, Ref, Outcome).
#+end_src

Status can distinguish:

#+begin_src prolog
current(Ref).
stale(OldRef, CurrentRef).
missing_version(OldRef, CurrentRef).
missing(Ref).
#+end_src

This is useful for agents/graphs because a checkpoint can safely retain an old ref and the fresh process can resolve it to current state while preserving evidence that supersession happened.

* 26. Adaptive recursion: recurse only when it wins

The adaptive layer does not treat “more recursion” as automatically smarter.

Canonical routes include:

- =direct_continuation=;
- =deterministic_context=;
- =cheap_submodel=;
- =recursive_rlm=;
- =delegated_subagent=.

Ask for a decision:

#+begin_src prolog
Signals = _{
    task_complexity:0.8,
    context_chars:180000,
    uncertainty:0.7,
    branch_diversity:0.3,
    progress:1.0,
    duplicate:false,
    current_depth:0,
    remaining_calls:4,
    remaining_tokens:8000,
    deterministic_context_available:true,
    cheap_submodel_available:false,
    delegated_subagent_available:false,
    artifact_context_available:true
},
recursion_route(Signals, [], Outcome).
#+end_src

The policy compares expected utility with estimated cost and selects a bounded candidate set.

The design target is:

#+begin_quote
Choose the cheapest bounded execution form with enough expected utility.
#+end_quote

not:

#+begin_quote
Recurse until max depth.
#+end_quote

* 27. Depth greater than one is deliberately gated

Normal production recursion is depth 1.

Merely setting:

#+begin_src prolog
max_recursion_depth(4)
#+end_src

is not enough for deeper adaptive recursion.

The experimental deep-recursion path requires both:

#+begin_src prolog
allow_deep_recursion(true).
deep_recursion_capability(true).
#+end_src

There are also duplicate-subproblem and no-progress guards:

#+begin_src prolog
recursion_fingerprint(Subject, Fingerprint).
recursion_guard(
    Fingerprint,
    PreviousFingerprints,
    Progress,
    Options,
    Outcome).
#+end_src

This is a better mental model than pretending “recursive” means uncontrolled self-calling.

* 28. MCP is a protocol boundary, not the core model backend

=rlm_mcp= normalizes MCP into version-neutral Prolog terms.

Supported protocol generations in the current implementation are:

- =2025-11-25= -- sessionful initialize/initialized lifecycle;
- =2026-07-28= -- stateless self-describing requests with =server/discover=.

Canonical commands look like:

#+begin_src prolog
list_tools.
list_tools(Cursor).
call_tool(Name, Arguments).
list_resources.
read_resource(Uri).
list_prompts.
get_prompt(Name, Arguments).
#+end_src

The rest of the runtime should not care about protocol-date strings, JSON-RPC method names, session headers, or 2026 routing headers.

The architecture is:

#+begin_example
transport
  -> protocol detection / negotiation
  -> version adapter
  -> canonical mcp_command{}
  -> canonical dispatch
  -> version adapter
  -> transport response
#+end_example

A critical design decision: MCP Sampling is not promoted into the core inference path. OpenRouter/OpenAI-compatible provider code remains the model-completion backend; MCP is used for tools/resources/prompts and protocol interoperability.

* 31. Debugging playbook

**Case: context operation returns the wrong data**

Reproduce through =rlm_context= directly. Inspect the handle metadata and =context_trace/3=. Do not start by changing planner prompts.

**Case: model returned a plan but nothing executed**

Run =plan_parse/2=, then =plan_validate/4=. Inspect the normalized AST and required capability set. A rejected plan is supposed to have no side effects.

**Case: tool is named correctly but denied**

Check both the plan capabilities and the registry schema's declared capability. Then verify the child/root authority boundary.

**Case: tool is allowed but handler never runs**

Check schema validation first. Authorization occurs before arguments/handler execution, and malformed args also fail before the handler.

**Case: completion runs out of model calls unexpectedly**

Count the root planner call plus every model step, recursive model step, retry multiplier, and planner retry. Budgets are shared, not reset per nested plan.

**Case: child RLM can use a root-only tool**

That is a bug. Inspect =child_capabilities= and recursive plan validation. Children must narrow authority.

**Case: agent count is high and machine threads explode**

That violates the runtime design. Logical agents should live in engines/state machines while blocking work is constrained by the shared worker pool.

**Case: graph resumes by repeating a side effect**

Inspect interrupt semantics and persisted next-node state. An interrupt applies its patch and resolves the outgoing edge before pause so resume should not blindly repeat the interrupting node.

**Case: fresh root has huge prompt history**

You are probably confusing durable artifact context with transcript replay. Build an explicit bounded artifact pack instead.

**Case: MCP protocol condition leaks into agent/graph code**

Move it back behind =rlm_mcp= / version adapters. Protocol-date branching is supposed to stop at that boundary.

* 32. How to extend the runtime safely

Suppose you want to add a new context transform named =normalize_whitespace=.

A disciplined implementation order is:

1. define exact semantics and bounds;
2. add it to the closed context transform vocabulary;
3. implement the deterministic transform in =rlm_context=;
4. add positive and negative context tests;
5. expose the operation through typed-plan normalization if required;
6. ensure capability derivation remains =context(map)= rather than inventing ambient authority;
7. test plan validation and execution;
8. test output-byte and time limits;
9. run the whole deterministic suite;
10. add/update docs only after behavior is executable.

Suppose instead you want a new side-effecting operation.

Do *not* put it into context =map=. Make it a capability-gated tool or another explicit trusted runtime boundary.

That distinction is foundational:

#+begin_example
pure bounded data projection -> context runtime
side effect / host capability -> trusted tool or dedicated subsystem
#+end_example

* 33. Major project: build a bounded repository-analysis RLM

The capstone is to build an RLM that analyzes a source repository without giving the model ambient filesystem execution.

The target flow:

#+begin_example
repository root
   |
   v
project_read tool registry
   |
query + opaque task context
   |
root planner
   |
   +--> bounded context slice/search
   +--> project_read selected files
   +--> optional depth-1 child model
   |
structured result
   |
selected durable artifact
#+end_example

**Step 1: create the tool registry**

#+begin_src prolog
tool_registry_create(Registry),
register_project_read_tool(
    Registry,
    '/path/to/project',
    [max_file_bytes(16384), time_limit(1.0)],
    ok(_)).
#+end_src

**Step 2: define the root authority**

#+begin_src prolog
RootCaps = [
    rlm,
    context(search),
    context(slice),
    tool(project_read),
    model(openrouter)
].
#+end_src

**Step 3: narrow child authority**

Start with:

#+begin_src prolog
ChildCaps = [model(openrouter)].
#+end_src

The child may reason over selected material but cannot independently read arbitrary additional project files.

**Step 4: use a small opaque task context**

#+begin_src prolog
TaskContext = text(
    "Find the runtime entrypoint, identify the execution safety boundary, and explain which module owns recursive execution.").
#+end_src

**Step 5: make the planner select evidence rather than dump the repository**

Grant only a small number of context/tool operations:

#+begin_src prolog
budget(_{
    max_recursion_depth:1,
    max_model_calls:4,
    max_tool_calls:3,
    max_context_ops:2,
    max_total_tokens:10000,
    max_cost_usd:0.25,
    max_output_bytes:32768,
    time_limit:120.0
}).
#+end_src

**Step 6: run =rlm_completion/4=**

#+begin_src prolog
rlm_completion(
    "Analyze the repository using only bounded evidence and return the architecture summary.",
    TaskContext,
    [ capabilities(RootCaps),
      child_capabilities(ChildCaps),
      tool_registry(Registry),
      budget(Budget)
    ],
    Outcome).
#+end_src

**Step 7: inspect the trajectory**

Do not read only =Result.value=. Verify:

- which context operations ran;
- which files were selected;
- tool authorization status;
- model-call count;
- actual recursion depth;
- child capability set;
- token/cost metadata when known;
- whether any plan was rejected/retried.

**Step 8: publish only the useful result**

Open an artifact store and save a compact summary/finding with provenance. Do not store the full provider transcript as the default durable state.

**Step 9: start a fresh root**

Build an artifact context pack and use it in a later task. Confirm the new root can continue from selected durable findings without receiving the entire earlier conversation.

**Step 10: add a graph around the workflow**

Wrap the stages in a graph:

#+begin_example
collect_evidence
      |
      v
analyze
      |
      v
review
   /      \
retry   publish
           |
           v
          end
#+end_example

Use a bounded loop for review/retry. Add an interrupt before publication if you want a human approval gate.

This project forces you to use the repository's actual architecture instead of treating it as “LLM calls Prolog somehow.”

* 34. Major project extension: adaptive routing

After the capstone works, stop forcing every task through recursion.

Compute routing signals from the task:

- context size;
- uncertainty;
- task complexity;
- branch diversity;
- remaining model calls/tokens;
- whether deterministic context operations can solve it;
- whether a cheap model or delegated agent is available.

Use =recursion_route/3= first.

Expected behavior should look like:

#+begin_example
small exact extraction
    -> deterministic_context

small semantic question
    -> direct_continuation or cheap_submodel

huge decomposable context
    -> recursive_rlm

tool-heavy branching investigation
    -> delegated_subagent
#+end_example

Measure whether routing actually improves cost/latency/quality under fixed budgets. If it does not, change the policy instead of assuming more layers equal more intelligence.

* 35. Common mistakes

**Mistake: “RLM means recursively call the model a bunch.”**

No. Recursion is one bounded strategy among several.

**Mistake: “Prolog plan means eval model-generated Prolog.”**

No. The plan language is a closed AST and JSON model output never falls back to arbitrary =read_term/3= execution.

**Mistake: “If the tool exists, the model can use it.”**

No. It needs registration *and* capability authorization.

**Mistake: “A child inherits everything.”**

No. Child authority is narrowing-only.

**Mistake: “A retry gets a fresh budget.”**

No. Runtime counters remain consumed.

**Mistake: “Graph state is agent memory.”**

Not exactly. Graph checkpoints are resumable execution state. Artifacts are cross-run selected durable knowledge. Provider transcript is a third thing.

**Mistake: “MCP should be the model backend.”**

Not in this architecture. Provider-native model completion remains separate.

**Mistake: “TODO says unchecked, so it is unimplemented.”**

Not currently. Check code and tests.

* 38. Final mental model

Keep this model in your head:

#+begin_example
LLM
  chooses strategy
       |
       v
closed symbolic data
       |
       v
Prolog supervisor
  validates
  authorizes
  budgets
  executes
  traces
       |
       +--> opaque context operations
       +--> model providers
       +--> trusted tools
       +--> bounded recursive calls
       +--> supervised agents
       +--> durable graphs
       +--> durable artifacts
       +--> canonical MCP
       |
       v
structured outcome
#+end_example

The point is not “use Prolog because Prolog is cool.”

The point is that Prolog is being used as a constrained symbolic control substrate: explicit terms, validation, rules, search, structured failure, capabilities, supervision, and durable state around probabilistic model decisions.

That is the architecture to preserve when extending =prolog-rlm=.
