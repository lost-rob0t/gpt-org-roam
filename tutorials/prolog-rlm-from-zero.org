* Goal

This is a code-first tutorial for learning =prolog-rlm= well enough to run it, debug it, extend it, and build bounded agentic RLM systems on top of it.

It was written from the current =main= implementation, tests, and runtime documentation. It is deliberately not a generic “what is an RLM?” article.

By the end you should be able to:

- explain why =prolog-rlm= keeps large context behind opaque handles;
- trace a root RLM call from model planner to typed plan to validated execution;
- configure OpenRouter or another OpenAI-compatible provider;
- execute typed plans without an LLM first;
- register capability-gated tools without exposing arbitrary =call/1=;
- distinguish =llm_query/3=, =rlm_query/4=, and =rlm_completion/4=;
- reason about recursion, capability narrowing, cancellation, cost, token, tool, context, output, and wall-time budgets;
- use structured outcomes, bounded inspection, and plan repair;
- create supervised logical agents with finite mailboxes and bounded worker pools;
- compile and run durable state graphs with interrupts and resume;
- persist selected artifacts without treating transcripts as memory;
- understand adaptive recursion routing and its duplicate/no-progress guards;
- understand the canonical MCP boundary;
- run deterministic and live benchmark modes;
- build a bounded repository-analysis RLM as a capstone.

* 1. What prolog-rlm actually is

The repository describes itself as a Prolog-native language-model harness and agent runtime built around Recursive Language Models.

The central architectural rule is:

#+begin_quote
The language model chooses semantic strategy; Prolog owns execution semantics.
#+end_quote

That means the LLM can propose decomposition, context operations, model calls, tool calls, recursive work, and agent work. It does *not* receive unrestricted Prolog execution.

The control shape is roughly:

#+begin_example
query + external context
          |
          v
  opaque context handle
          |
          v
   root planner model
          |
          v
   typed symbolic plan
          |
          v
Prolog parse + validation
          |
          +--> capability check
          +--> budget check
          +--> provider/tool preflight
          +--> recursion guard
          |
          v
 bounded execution + trace
          |
          v
 structured outcome
#+end_example

This is not “let the model generate Prolog and =call/1= it.” The plan language is closed and model text is treated as data.

* 5. Opaque context: the first RLM primitive

Import the lower-level context module when experimenting directly:

#+begin_src prolog
:- use_module('prolog/rlm_context').
#+end_src

The memory backend accepts explicit text or term payloads:

#+begin_src prolog
context_register(text(Text), Options, Outcome).
context_register(terms(Terms), Options, Outcome).
#+end_src

Example:

#+begin_src prolog
?- context_register(
       text("alpha\nbeta needle\ngamma\nneedle delta\n"),
       [],
       ok(Ref)),
   get_dict(handle, Ref, Handle).
#+end_src

The result contains an opaque versioned handle plus metadata. The payload does not automatically become part of every model prompt.

The memory backend advertises =filesystem:false= and =network:false=. Passing =file(Path)= or =url(URL)= does not cause ambient dereferencing.

The documented default operation bounds are:

#+begin_src prolog
[max_results(32), max_bytes(16384), time_limit(0.25)]
#+end_src

* 6. Learn context operations without an LLM

With =Handle= from the previous section:

#+begin_src prolog
?- context_peek(Handle, head(12), [], Peek).
?- context_slice(Handle, 6, 20, [], Slice).
?- context_search(Handle, "needle", [], Search).
?- context_partition(Handle, lines(2), [], Parts).
?- context_map(Handle, lowercase, [], Lower).
?- context_reduce(Handle, count, [], Count).
?- context_trace(Handle, 20, Trace).
#+end_src

The important part is not the syntax. It is the *closed vocabulary*.

Current map transforms include things like:

- =identity=;
- =lowercase=;
- =uppercase=;
- =length=.

Reducers include:

- =count=;
- =byte_count=.

The model cannot smuggle an arbitrary Prolog predicate into =context_map/4=.

**Exercise:** register =terms([person(alice), person(bob), relation(alice,bob)])=. Compare term =peek=, =slice=, =search=, =map(length)=, and =reduce(count)=.

* 7. Typed plans are the execution boundary

Import the plan runtime:

#+begin_src prolog
:- use_module('prolog/rlm_plan').
#+end_src

The public flow is:

#+begin_src prolog
plan_parse(+ModelOutput, -Outcome).
plan_normalize(+PlanLike, -Outcome).
plan_validate(+Plan, +Capabilities, +Budget, -Outcome).
plan_execute(+ValidatedPlan, +RuntimeOptions, +Inputs, -Outcome).
plan_run(+PlanLike, +Capabilities, +RuntimeOptions, +Inputs, -Outcome).
#+end_src

The closed AST includes:

#+begin_src prolog
context(HandleExpr, Action, Bind).
model(ProviderName, PromptExpr, RequestOptions, Bind).
rlm(SubPlan, Bind).
tool(ToolName, ArgsExpr, Bind).
parallel(SubPlans, Bind).
retry(Attempts, SubPlan, Bind).
checkpoint(Label).
final(ValueExpr).
#+end_src

Closed expressions include:

#+begin_src prolog
literal(Value).
input(Name).
var(Name).
field(BaseExpr, Key).
list(Exprs).
object(KeyExprPairs).
#+end_src

JSON planner output is decoded as JSON. The runtime does not fall back to reading arbitrary model-produced Prolog source as the control path.

* 8. Execute a plan before involving a model

This is the fastest way to separate plan bugs from planner bugs.

Assume =Handle= is a registered context handle:

#+begin_src prolog
Plan = plan([
    context(input(context), search("needle"), hits),
    final(var(hits))
]),
Caps = [context(search)],
Inputs = _{context:Handle},
plan_run(Plan, Caps, [], Inputs, Outcome).
#+end_src

Whole-plan validation checks things such as:

- every operation belongs to the closed vocabulary;
- =final/1= appears once and last;
- variables are bound before use;
- bindings are not reused;
- context selectors/actions are allowed;
- requested capabilities are granted;
- nested recursion/retry/parallel plans are valid;
- worst-case static counts fit the plan budget;
- named providers and tools can be preflighted before the first side effect.

A plan rejected during validation should not half-execute.

* 9. Capabilities are authority, not labels

Capabilities are ordinary closed terms:

#+begin_src prolog
context(search).
context(slice).
model(openrouter).
tool(project_read).
rlm.
parallel.
retry.
checkpoint.
filesystem(read).
network(http).
process(exec).
mcp(tools).
#+end_src

A model naming =project_read= does not grant =tool(project_read)=.

Child capabilities are narrowing-only:

#+begin_src prolog
?- use_module('prolog/rlm_tool').
?- capabilities_narrow(
       [rlm, model(openrouter), tool(project_read)],
       [model(openrouter)],
       Outcome).
#+end_src

That succeeds.

This must fail:

#+begin_src prolog
?- capabilities_narrow(
       [model(openrouter)],
       [model(openrouter), tool(project_read)],
       Outcome).
#+end_src

A child may drop authority, not invent it.

* 10. Trusted tools

The host creates a registry, supplies schemas, and supplies trusted handlers:

#+begin_src prolog
tool_registry_create(Registry).
tool_register(Registry, Schema, Handler, Outcome).
tool_discover(Registry, Schemas).
tool_lookup(Registry, Name, Outcome).
tool_invoke(Registry, Caps, Name, Args, Options, Outcome, Trace).
tool_registry_destroy(Registry).
#+end_src

A small custom tool:

#+begin_src prolog
count_text(Args, Count) :-
    get_dict(text, Args, Text),
    string_length(Text, Count).

count_text_schema(
    tool_schema{
        name:count_text,
        description:"Count characters in a string",
        capability:tool(count_text),
        arguments:_{
            type:object,
            required:[text],
            additional_properties:false,
            properties:_{text:_{type:string}}
        },
        result:_{type:integer},
        limits:tool_limits{
            time_limit:1.0,
            max_output_bytes:1024
        }
    }).
#+end_src

Use it:

#+begin_src prolog
tool_registry_create(Registry),
count_text_schema(Schema),
tool_register(Registry, Schema, user:count_text, ok(_)),
tool_invoke(
    Registry,
    [tool(count_text)],
    count_text,
    _{text:"prolog"},
    [],
    Outcome,
    Trace).
#+end_src

Authorization occurs before handler execution. Args and results are schema checked. Wall time and output bytes are bounded. The model can select the registered *name* but never supplies =user:count_text=.

* 11. The built-in project_read boundary

The first real local tool is intentionally narrow:

#+begin_src prolog
register_project_read_tool(
    Registry,
    '/srv/project',
    [max_file_bytes(8192), time_limit(1.0)],
    Outcome).
#+end_src

It requires:

#+begin_src prolog
tool(project_read)
#+end_src

It reads one regular UTF-8 file below the configured root. Absolute paths, traversal, backslash paths, NUL paths, and symlink components are rejected.

Registering it does not grant general =filesystem(read)=, shell, process, or network authority.

Typed-plan integration:

#+begin_src prolog
Caps = [tool(project_read)],
tool_registry_runtime_tools(Registry, Caps, RuntimeTools),
plan_run(
    Plan,
    Caps,
    [tools(RuntimeTools)],
    Inputs,
    Outcome).
#+end_src

Notice the two boundaries:

1. plan validation requires =tool(project_read)=;
2. the registry rechecks authorization when invoking the handler.

* 13. llm_query, rlm_query, and rlm_completion are different layers

The public facade exports all three.

**Direct bounded model call**

#+begin_src prolog
llm_query(
    "Reply with OK.",
    [budget(_{max_total_tokens:256, max_cost_usd:0.05})],
    Outcome).
#+end_src

**Bounded recursive child query**

#+begin_src prolog
rlm_query(
    "Summarize the child context.",
    text("child context"),
    [depth(1), budget(_{max_recursion_depth:1})],
    Outcome).
#+end_src

**Full root RLM supervisor**

#+begin_example
rlm_completion/4
   |
   +--> acquire/register opaque context
   +--> build root planner prompt
   +--> call planner provider
   +--> parse typed plan
   +--> recursive/capability validation
   +--> execute plan
   +--> aggregate usage + transitions
   +--> structured result
#+end_example

Do not invoke the full root planner when one direct model call is enough.

* 14. Completion budgets are shared control state

The current default completion budget is:

#+begin_src prolog
completion_budget{
    max_iterations:32,
    max_recursion_depth:1,
    max_concurrent_subcalls:2,
    max_model_calls:4,
    max_tool_calls:4,
    max_context_ops:8,
    max_total_tokens:8192,
    max_cost_usd:0.25,
    max_output_bytes:32768,
    time_limit:30.0
}.
#+end_src

Default root authority is:

#+begin_src prolog
[rlm, model(openrouter)]
#+end_src

Default child authority narrows to:

#+begin_src prolog
[model(openrouter)]
#+end_src

A root planner call consumes model budget too. Nested plans, retries, recursive calls, tool calls, context operations, and intermediate output do not get magically fresh budgets.

This is one of the most important things to understand when debugging “why did my RLM stop early?”

The repository's live OpenRouter acceptance test exercises the actual production path:

* 16. Cancellation is a first-class control signal

Create a token:

#+begin_src prolog
rlm_cancellation_token(Token).
#+end_src

Pass it:

#+begin_src prolog
[cancel_token(Token)]
#+end_src

Cancel it from another control path:

#+begin_src prolog
rlm_cancel(Token).
#+end_src

The implementation actively signals the thread running the completion. Cancellation and time-limit exceptions remain control signals instead of being swallowed as ordinary model/tool failures.

The deterministic tests cover both pre-planner cancellation and cancellation while a model call is pending.

* 17. Structured outcomes and bounded repair

The outcome layer distinguishes:

- =success=;
- =logical_failure=;
- =timeout=;
- =depth_exhausted=;
- =resource_exhausted=;
- =capability_denied=;
- =validation_failure=;
- =exception=.

That matters in Prolog: logical failure is not the same thing as an exception.

Inspect a plan without running it:

#+begin_src prolog
plan_inspect(Plan, Capabilities, Budget, Inspection).
#+end_src

Inspect predicate metadata:

#+begin_src prolog
predicate_inspect(my_module:worker(_), Inspection).
#+end_src

Wrap a trusted host goal:

#+begin_src prolog
goal_outcome(member(X, [a,b]), [], Outcome).
#+end_src

Repair API:

#+begin_src prolog
plan_repair(
    Plan,
    Capabilities,
    RuntimeOptions,
    Inputs,
    TrustedRepairHandler,
    Outcome).
#+end_src

The repair handler receives a structured observation containing phase, status, error, bounded trace, and remaining budget.

The critical invariant is:

#+begin_quote
Repair does not reset consumed execution budget.
#+end_quote

A validation failure may be repaired before consuming execution counters. A tool/model/runtime failure has already spent some budget.

* 18. Supervised logical agents

The agent runtime uses SWI engines/state machines, finite message queues, and one bounded worker pool per runtime.

It explicitly avoids one permanently blocked OS thread per logical agent.

Public lifecycle:

#+begin_src prolog
agent_runtime_create(+Options, -Runtime).
agent_runtime_destroy(+Runtime).
agent_runtime_status(+Runtime, -Status).
agent_spawn(+Runtime, +Parent, +Spec, +Capabilities, -Outcome).
agent_send(+Runtime, +Agent, +Message, +Options, -Outcome).
agent_pump(+Runtime, +Agent, +Options, -Outcome).
agent_status(+Runtime, +Agent, -Outcome).
agent_children(+Runtime, +Agent, -Children).
agent_cancel(+Runtime, +Agent, +Reason, -Outcome).
agent_trace(+Runtime, -Events).
#+end_src

Minimal supervision tree:

#+begin_src prolog
run_agents :-
    setup_call_cleanup(
        agent_runtime_create(
            [root_capabilities([
                 tool(spawn_agent),
                 tool(read)
             ])],
            Runtime),
        (
            agent_spawn(
                Runtime,
                none,
                agent_spec(root),
                [tool(spawn_agent), tool(read)],
                ok(Root)),
            agent_spawn(
                Runtime,
                Root,
                agent_spec(child),
                [tool(read)],
                ok(Child)),
            agent_children(Runtime, Root, Children),
            format('root=~q child=~q children=~q~n',
                   [Root, Child, Children])
        ),
        agent_runtime_destroy(Runtime)).
#+end_src

The child cannot request a capability absent from the parent.

* 19. Mailboxes, worker pools, and agent plan integration

The mailbox protocol uses a closed vocabulary around terms such as:

#+begin_src prolog
request(RunId, CallId, Work).
result(CallId, Result).
spawn(Parent, Child, Spec, Capabilities).
cancel(RunId, Reason).
checkpoint(RunId, Label).
budget_exhausted(RunId, Kind).
#+end_src

Mailboxes are finite, so saturation becomes an explicit backpressure outcome rather than unbounded memory growth.

Blocking host work goes through a bounded pool configured with things like:

#+begin_src prolog
worker_count(2).
worker_backlog(8).
worker_handler(my_module:worker_handler).
#+end_src

The typed-plan =spawn_agent= form is sugar over the normal tool boundary:

#+begin_src prolog
plan([
    spawn_agent(agent_spec(child), [tool(read)], child),
    final(var(child))
]).
#+end_src

It normalizes to a =tool(spawn_agent,...)= operation. The host supplies the trusted adapter:

#+begin_src prolog
[tools([
    tool(spawn_agent,
         rlm:agent_tool_handler(Runtime, Parent))
])]
#+end_src

So spawning still requires =tool(spawn_agent)=, consumes normal plan/tool budget, and does not introduce a second unsafe evaluator.

* 20. Durable state graphs

Graphs are declarative data. Trusted handlers and routers live in a separate host registry.

A complete tiny graph example:

#+begin_src prolog
increment(_State, _Context, update(_{count:1})).

run_graph(Outcome) :-
    Spec = graph(
        counter,
        [field(count, integer, 0, sum)],
        [node(increment, increment_handler)],
        [edge(start, increment),
         edge(increment, end)]
    ),
    Registry = [
        handler(increment_handler, user:increment)
    ],
    graph_compile(Spec, Registry, [], ok(Compiled)),
    graph_run(Compiled, _{}, [], Outcome).
#+end_src

Graph compilation validates before execution:

- unique state fields;
- unique node names;
- reserved =start=/=end= rules;
- exactly one edge leaving =start=;
- no outgoing edge from =end=;
- registered handler/router references;
- edge targets;
- reachability;
- structural path to =end=.

Closed state reducers include =replace=, =append=, and =sum=. Supported state types include atom, string, integer, number, boolean, list, dict, and any.

Loops are allowed structurally, but total steps and per-node visits are bounded at runtime.

* 21. Interrupt, checkpoint, and resume

Open a memory backend:

#+begin_src prolog
graph_backend_open(memory, Backend).
#+end_src

A node may return:

#+begin_src prolog
interrupt(needs_approval, _{status:waiting}).
#+end_src

Run with a stable ID:

#+begin_src prolog
graph_run(
    Compiled,
    _{},
    [backend(Backend), run_id(review_42)],
    ok(Paused)).
#+end_src

Resume:

#+begin_src prolog
graph_resume(
    Compiled,
    Backend,
    review_42,
    approved,
    [],
    Outcome).
#+end_src

A resume value can include an atomic state patch:

#+begin_src prolog
resume(approved, _{approved:true})
#+end_src

Persistent journal:

#+begin_src prolog
graph_backend_open(
    persist('/var/lib/my-app/graph.db'),
    Backend).
#+end_src

The repo tests persistence across two separate =swipl= processes. That matters: executable closures are loaded again from code, while only serializable graph snapshots/events persist.

Interrupt semantics also avoid blindly replaying the interrupting side effect: the patch and outgoing edge are resolved before the run is paused.

* 22. Durable artifacts are not transcripts

Keep three concepts separate:

#+begin_example
provider/model transcript
    -> model interaction history

graph checkpoint
    -> execution state needed to resume a graph

artifact store
    -> selected durable summaries/findings/blackboards for later work
#+end_example

Open a store:

#+begin_src prolog
artifact_store_open(memory, ok(Store)).
#+end_src

Publish an immutable version:

#+begin_src prolog
artifact_put(
    Store,
    [project, demo],
    working_summary,
    summary,
    _{text:"bounded durable state"},
    _{producer:manual_tutorial},
    Outcome).
#+end_src

Build a bounded context pack for a fresh root:

#+begin_src prolog
artifact_context_pack(
    Store,
    [project, demo],
    [max_items(8), max_chars(4000), consumer(next_root)],
    Outcome).
#+end_src

A new root receives the selected compact artifact state, not an implicit replay of all prior conversation.

New writes to a namespace/key supersede older versions without deleting history. =artifact_ref_status/3= can distinguish current, stale, missing-version, and missing refs.

* 23. Adaptive recursion means “choose a route,” not “recurse harder”

Canonical routes include:

- =direct_continuation=;
- =deterministic_context=;
- =cheap_submodel=;
- =recursive_rlm=;
- =delegated_subagent=.

Ask for a route:

#+begin_src prolog
Signals = _{

* 24. MCP is a protocol boundary, not the inference backend

=rlm_mcp= gives the rest of the runtime a canonical Prolog representation of MCP.

The current implementation supports:

- =2025-11-25= -- legacy initialize/initialized lifecycle with optional session state;
- =2026-07-28= -- stateless self-describing requests with =server/discover=.

Canonical commands look like:

#+begin_src prolog
list_tools.
list_tools(Cursor).
call_tool(Name, Arguments).
list_resources.
read_resource(Uri).
list_prompts.
get_prompt(Name, Arguments).
#+end_src

The desired dependency direction is:

#+begin_example
transport
  -> protocol negotiation/detection
  -> version adapter
  -> canonical mcp_command{}
  -> canonical dispatch
  -> version adapter
  -> transport
#+end_example

Protocol dates, JSON-RPC method strings, routing headers, and legacy session state should not leak into agent, graph, plan, completion, or chain semantics.

MCP Sampling is not the core model path here. Provider-native model completion remains separate.

* 27. Debugging playbook

**Context operation returns bad data**

Call =rlm_context= directly. Inspect metadata and =context_trace/3=. Do not begin by tweaking the LLM prompt.

**Planner returns something but no plan runs**

Call =plan_parse/2= and =plan_validate/4=. Inspect the normalized AST and capability requirements.

**Tool name is correct but denied**

Check the active capability set and the schema's declared =tool(Name)= capability. Then check whether you crossed a root/child narrowing boundary.

**Tool never reaches its handler**

Authorization and argument schema validation happen first. A malformed call should not reach trusted code.

**Model-call budget disappears too fast**

Count the root planner call, planner retries, plan model steps, recursive model steps, and retry multipliers. Nested execution shares budgets.

**Child uses a root-only tool**

Treat that as a bug. Child authority must be a subset and recursive plan validation is supposed to reject widening.

**Twenty logical agents cause twenty idle OS threads**

That violates the runtime architecture. Logical state belongs in engines; blocking work belongs in the bounded worker pool.

**Graph resumes by repeating the interrupt side effect**

Inspect the persisted next node and interrupt semantics. The runtime should resolve the transition before pause.

**Fresh root prompt contains the full prior transcript**

You are probably using chat history where you meant durable artifacts. Build a bounded artifact pack.

**MCP protocol date appears inside agent/graph code**

Push that version-specific behavior back into the MCP adapter boundary.

* 28. Extend the system without breaking its core safety model

Suppose you want a new pure context transform =normalize_whitespace=.

Use this order:

1. define exact deterministic semantics;
2. add it to the closed transform vocabulary;
3. implement it in =rlm_context=;
4. add positive and negative context tests;
5. expose it through plan normalization only if needed;
6. keep the authority under =context(map)=;
7. test plan validation and execution;
8. test byte/time limits;
9. run the full deterministic suite;
10. update docs after behavior exists.

If the new operation has a side effect, do *not* stuff it into context =map=. Put it behind a trusted tool or dedicated capability boundary.

#+begin_example
pure bounded projection
    -> context runtime

side effect / host authority
    -> trusted tool or dedicated runtime subsystem
#+end_example

That separation is foundational.

* 30. Project extension: adaptive routing

Once the capstone works, stop forcing every task through recursion.

Compute routing signals such as:

- context size;
- uncertainty;
- task complexity;
- branch diversity;
- remaining model calls/tokens;
- deterministic context availability;
- cheap submodel availability;
- delegated agent availability.

Then call =recursion_route/3= first.

A healthy policy should often look something like:

#+begin_example
exact extraction
    -> deterministic_context

small semantic task
    -> direct_continuation or cheap_submodel

large decomposable context
    -> recursive_rlm

branching tool-heavy investigation
    -> delegated_subagent
#+end_example

Benchmark the policy under fixed budgets. If recursion costs more without improving results, the answer is not “increase recursion depth.”

* 31. Common mistakes

**“RLM means recursively call the model repeatedly.”**

No. Recursion is one bounded execution route.

**“Typed plan means evaluate model-generated Prolog.”**

No. Plans are a closed AST and JSON model output remains data.

**“If the tool exists, the model can use it.”**

No. Registration and capability authorization are both required.

**“Children inherit all authority.”**

No. Child authority narrows.

**“Retries and repairs get fresh budgets.”**

No. Consumed runtime budget remains consumed.

**“Graph checkpoint equals long-term agent memory.”**

No. Checkpoint, artifact, and transcript are deliberately separate concepts.

**“MCP should be the model provider.”**

Not in this architecture. Provider-native inference remains separate.

**“TODO checkbox means implementation status.”**

Not currently. Verify source and tests.
