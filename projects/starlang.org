* What StarLang is

StarLang is the Common Lisp-only compiler and durable actor runtime used as a reusable runtime layer for StarIntel. The authoritative working implementation currently lives in =prototype/= under the =starlang-prototype= ASDF system while the code is incrementally extracted into final =star-*= and =starlang-*= systems.

StarLang is deliberately not implemented by feeding =.star= files to the Common Lisp reader. Its source is parsed by a closed parser, expanded through bounded declarative macros, validated, and compiled into normalized runtime-neutral IR.

* Core pipeline

#+begin_example
UTF-8 source bytes
  -> read-star-syntax
  -> locked import resolution
  -> expand-star-syntax
  -> validate-star-core
  -> compile-star-core
  -> normalized runtime-neutral IR
#+end_example

See [[id:dca7bf46-7062-4e34-bfaf-8bec6e520a42][StarLang Compiler and Runtime Architecture]].

* Main subsystems

- =starlang-compiler=: parser, syntax objects, validation, normalized IR, manifest generation.
- =starlang-runtime=: durable execution and runtime-facing APIs.
- =star-actor-protocol=: actor message/protocol definitions.
- =star-mailbox=: per-actor mailbox semantics.
- =star-supervisor=: supervision trees and restart strategies.
- =star-journal=: durable journal/replay boundary.
- =star-lease=: time-bound actor/resource leases.
- =star-capability=: capability/authorization surface.
- =star-artifact=: artifact/provenance handling.
- =star-adapter-sdk=: inbound/outbound adapter boundary.
- =star-http-port= and =star-process-port=: concrete external ports.
- =star-canonical-json=: deterministic JSON interchange.
- =star-sento-compat=: compatibility boundary to Sento / CL-GServer.

* Current status

The project explicitly describes itself as not yet fully conformant with the approved STAR-LANG research sequence 000-009. Do not confuse an approved design with completed implementation.

The =star://domain:address:actor-name= service URI work exists on the =agent/star-service-uri= branch / PR #14 at the time this tutorial node was authored. Treat it as incoming until merged.
